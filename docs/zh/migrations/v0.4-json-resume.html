v0.4 JSON Resume 结构迁移 ​

Web Resume v0.4 开始让新建及转换后的文档尽可能采用 JSON Resume 字段结构。旧版 YAML 在 v0.4 期间仍可直接读取，不会在加载时自动改写。

是否需要迁移 ​

如果文件使用 contact、project.sets、skill.sets、education.histories 等结构，它属于旧版格式。你可以继续使用，也可以转换后逐步接入 JSON Resume 生态。

标准格式通常使用 basics.email、projects[]、skills[]、education[] 等字段。YAML 或 JSON 只是文件语法，不影响采用 JSON Resume 数据结构。

在编辑器中转换 ​

  1. 在编辑器中加载旧版简历。
  2. 选择页面提示中的 检查并转换。
  3. 阅读需要人工处理的字段提示。
  4. 选择 转换并写回编辑器。
  5. 检查预览和 YAML；如需恢复，立即使用编辑器撤销。

只有确认后，编辑器文本才会改变。原始 URL 或磁盘文件不会被浏览器直接覆盖。

转换器不会擅自判断以下内容：

  • project 中的条目究竟是工作还是项目；
  • certificate 中的条目究竟是奖项、证书还是出版物；
  • 自由文本地址应如何拆分成城市、地区和国家；
  • 非标准日期应如何转换成 YYYY、YYYY-MM 或 YYYY-MM-DD。

无法安全转换的数据会尽量保存在 x-web-resume 中并显示提示。转换序列化暂时无法保留 YAML 注释，因此有注释时也会提示。

转换器不认识的字段会保存在 x-web-resume.legacyFields 中。键名采用字段原始位置的 JSON Pointer 路径，既能恢复自定义数据，也不需要复制整份旧版文档。

使用命令行转换 ​

只检查，不写文件：

bash
pnpm migrate:resume -- --input ./resume.yml --check

旧格式需要迁移或校验失败时，检查命令以状态码 1 退出。

生成一份转换后的副本：

bash
pnpm migrate:resume -- --input ./resume.yml --output ./resume.v0.4.yml

命令不会隐式覆盖输入文件。建议先查看转换提示并比较差异，再决定是否替换原文件。

板块标题、图标、条目 Logo、展开状态、徽章、自定义资料、other 内容和展示顺序统一放在 x-web-resume 扩展中。

兼容与回退 ​

  • v0.4 保留旧版格式的加载和渲染能力。
  • 标准无法表达的展示信息只使用根级 x-web-resume 扩展。
  • 浏览器转换是一次可撤销操作；命令行转换默认写入新文件。
  • volunteer、publications、languages、interests 和 references 等标准板块均可渲染。
  • 未来如果移除旧格式读取，必须随稳定版数据契约提供迁移说明和经过测试的转换路径。

更完整的字段取舍与设计依据见 JSON Resume 兼容性评估，英文版见 v0.4 migration guide。
